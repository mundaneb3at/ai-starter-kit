# Scope first

**Use when** the task is open-ended, multi-step, or hard to reverse — anything
phrased as "build / add / create / redesign / migrate X." Skip it for a trivial,
obvious one-liner.

## Steps

1. **Restate the goal in one sentence** and confirm it. ("You want X so that Y —
   correct?") Catching a misunderstanding here is free; catching it after
   building is expensive.
2. **Surface the unknowns.** Ask only the 1-3 questions whose answers would
   actually change the approach. One question at a time — don't stack them.
3. **Sketch the approach** in a few lines, and name the main risk or trade-off.
4. **Get a go-ahead**, then do the **smallest first step** and check it before
   continuing.

## Avoid

- Jumping straight to implementation on a vague request.
- Asking ten clarifying questions when two would do.
- Presenting a giant plan instead of the first concrete step.
